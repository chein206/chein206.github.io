SCPAD 시스템 구조

자동차 SC 견적·CRM SaaS — Vanilla JS 단일 HTML + Vercel Serverless + Supabase (app.scpadlab.com)

구조를 고른 기준은 하나였습니다 — 혼자서 유지할 수 있는가.

상시 켜두는 서버를 한 대도 두지 않았습니다. 정적 HTML + Serverless + 관리형 DB로 붙여 장애가 나도 제가 새벽에 일어날 일이 없는 형태로 맞췄습니다.

권한 검사는 애플리케이션이 아니라 DB의 RLS에 뒀습니다. 혼자 만들기 때문에 제 코드 실수가 곧 고객 데이터 사고가 되는 구조를 피하고 싶었습니다.

브랜드(BYD·BMW)는 배포를 나누지 않았습니다. 단일 코드베이스 + 런타임 분기로 두고 데이터만 brand 컬럼으로 격리했습니다 — 브랜드가 늘어도 배포 대상은 하나입니다.

브랜드 멀티테넌시

  • • 단일 코드베이스 + 런타임 분기 (?brand= / rewrites)
  • • 데이터는 brand 컬럼으로 완전 격리 (BYD / BMW)
  • • 브랜드 세션 격리 — 같은 도메인 교차 로그인 차단
  • • 브랜드별 PWA 아이콘 · 푸시 · 진입 URL

데이터 소유권 · 보안

  • • 권한 검사를 DB(RLS)에 — 앱 코드 실수로 뚫리지 않게
  • • 클라이언트는 anon key + RLS, 권한 작업만 service_role
  • • 시크릿 전부 환경변수 — 코드·저장소에 미포함
  • • 플랜 한도(profiles.features)는 서버에서 재검증

운영 자동화

  • • Cron 3종: 웹푸시 09:00 · 자동청구 10:00 · 정리 03:00 KST
  • • 월간 금융조건(IRR·이손금)은 어드민에서 DB로 — 무배포 갱신
  • • 결제는 빌링키 자동청구 + 해지 시 잔여일 부분환불
  • • 데모 계정 매일 시드 리셋 (실데이터와 RLS 격리)

믿을 수 있게 만드는 장치

  • • 금융 계산은 순수함수(hana-calc.js) — 앱과 테스트가 같은 파일
  • • 금융사 엑셀 견적서를 정답으로 두고 전차종 자동 대조
  • • OCR·AI 메시지는 정답셋 기반 평가 하네스로 회귀 확인
  • • AI가 불확실한 항목은 화면에 표시 — 사람이 확인
